# `fluid generate pyspark-schema`

*(since 0.37.0)* Writes a PySpark `StructType` module for each output port of a contract. A Spark job imports the module and reads or builds data with the contract's columns, types and nullability, instead of a schema written by hand.

forge-cli never imports `pyspark`. Only the generated module does, when a job imports it.

## Example

```bash
fluid generate pyspark-schema contract.fluid.yaml --out jobs/schemas
```

```text
Wrote 1 PySpark schema module(s) to jobs/schemas:
  orders_schema.py  output port 'orders', 3 columns (new)
```

For a port with three columns, the module reads:

```python
# Generated by `fluid generate pyspark-schema`. Do not edit: regenerate.
# -*- coding: utf-8 -*-
# fmt: off
# isort: skip_file

# data product: gold.sales.orders_v1
# output port: orders

from pyspark.sql.types import (
    DecimalType,
    StringType,
    StructField,
    StructType,
    TimestampType,
)

SCHEMA = StructType(
    [
        #: Order id
        StructField("order_id", StringType(), nullable=False),
        StructField("amount", DecimalType(12, 2), nullable=True),
        StructField("created", TimestampType(), nullable=True),
    ]
)
```

## Syntax

```bash
fluid generate pyspark-schema [CONTRACT] [--out DIR] [--env ENV] [--check]
```

| Option | Description |
| --- | --- |
| `CONTRACT` | The contract file (`contract.fluid.yaml`). |
| `--out`, `-o DIR` | Output directory. Default `runtime/pyspark_schema`. `fluid init` git-ignores `runtime/`, so pass the directory your jobs import from if you commit the modules. |
| `--env ENV` | Apply an environment overlay before generating. |
| `--check` | Write nothing. Exit 1 when a module is missing, differs from what the contract generates, or is no longer in the contract. For CI. |

The command writes `<port>_schema.py` for each output port that declares `contract.schema` columns. Each module defines `SCHEMA`.

It replaces only files it wrote itself for the same data product. It writes no `__init__.py` and deletes nothing.

[`fluid generate artifacts --emit pyspark-schema`](./generate-artifacts.md#pyspark-schema-modules) writes the same modules into a stage-3 tree and its MANIFEST.

## Use the module in a job

Put the directory on the job's path, then import `SCHEMA`.

```bash
spark-submit --py-files jobs/schemas/orders_schema.py jobs/load_orders.py
```

```python
from orders_schema import SCHEMA

df = spark.read.schema(SCHEMA).parquet("s3://bucket/orders/")
df = spark.createDataFrame(rows, SCHEMA)
parsed = raw.select(from_json(col("value"), SCHEMA).alias("order"))
```

## Type mapping

| Contract type | PySpark type |
| --- | --- |
| `string` family, `uuid`, `enum`, `char(n)`, `varchar(n)` | `StringType()` |
| `tinyint` | `ByteType()` |
| `smallint`, `int2`, `int16`, `year` | `ShortType()` |
| `int` family | `IntegerType()` |
| `bigint`, `long`, `int64` | `LongType()` |
| `float`, `real` | `FloatType()` (`float(p)` with p above 24 is `DoubleType()`) |
| `double` | `DoubleType()` |
| `boolean`, `bit` | `BooleanType()` |
| `date` | `DateType()` |
| `timestamp`, `datetime`, `timestamptz`, `timestamp_ltz` | `TimestampType()` |
| `timestamp_ntz`, `timestampntz`, `... without time zone` | `TimestampNTZType()` (Spark 3.3 and newer) |
| `binary` family | `BinaryType()` |
| `decimal(p,s)` | `DecimalType(p, s)`, p from 1 to 38 and s at most p |
| `decimal`, `number` with no parameters | `DecimalType(38, 9)` |
| `money` | `DecimalType(19, 4)` |
| `struct` | `StructType`, from the declared `fields` |
| `array` | `ArrayType`, from the declared `element` |
| `map` | `MapType`, from the declared `key` and `value` |

A struct, array or map declares its nested types in contract 0.7.7. Each level is typed. The depth limit is 32, and duplicate field names (compared without case) are refused.

A `char(n)` or `varchar(n)` column is a `StringType`: a DataFrame cannot hold `CharType` or `VarcharType`, so the length is a quality check, not part of the schema.

### Types written as a string

A type Spark has no form for is written as `StringType()` and the run warns. The column keeps its name and nullability.

| Contract type | Why |
| --- | --- |
| `json`, `jsonb`, `super` | Spark has no JSON type. |
| `variant` | `VariantType` needs Spark 4.0. |
| `time`, `interval` | Spark 3 has no such column type. |
| `bignumeric` | Wider than Spark's decimal. |

### Types that are refused

A type Spark cannot hold at all refuses the run, and nothing is written. The message names every such column and what to declare instead.

| Contract type | What to declare instead |
| --- | --- |
| `geography`, `geometry`, `geom`, `point`, `hll` | A `string` or `binary` column. |
| `bit(n)` with n above 1 | A `binary` column. |
| A decimal outside 1 to 38 digits | A decimal within Spark's limit. |
| A type with text after its parameters, such as `int(11) unsigned` or `timestamp(6) without time zone` | The plain type. Spark has no unsigned integers, and the type name carries the time zone. |
| A bare `struct`, `array` or `map` | Declare `fields`, `element`, or `key` and `value` (contract 0.7.7). |
| An unknown type | A type from the table above. |

A contract whose `exposes` or `contract.schema` is not a list is refused too, so a CI check never passes on a contract it cannot read.

## Nullability

| Contract | Module |
| --- | --- |
| `required: true` on a column | `nullable=False` |
| `required: true` on an array element | `containsNull=False` |
| `required: true` on a map value | `valueContainsNull=False` |
| A map key | Never null |

Spark's file sources (Parquet and others) and `from_json` read every column as nullable, whatever the schema says. On those, `nullable=False` documents the contract. `spark.createDataFrame` checks it.

## Comments and header

A column description becomes one `#:` comment line above the field, cut to 80 characters. No field metadata is written, so `df.schema == SCHEMA` stays true for a schema read from storage.

The header carries the data product id and the port id as comments, plus `# fmt: off` and `# isort: skip_file`. There is no timestamp and no version, so the output is stable and safe to commit.

A module is a program a job imports. Contract text reaches it only as string literals and as comment or docstring lines with control characters replaced. It never appears on the first two lines, because an encoding declared there would change how Python decodes the file. The command checks every module against an allowlist of what it may hold before it writes it.

## Keep committed modules current

Commit the modules and fail CI when they drift:

```bash
fluid generate pyspark-schema contract.fluid.yaml --out jobs/schemas --check
```

`--check` writes nothing. It exits 1 when a module is missing, differs from what the contract generates, or a `*_schema.py` this command wrote for the same data product is no longer in the contract. A normal run only notes the stale file and deletes nothing. Modules of another data product in the same directory are not reported.

## Sharing a directory

Two data products may share an `--out` only if their port ids differ. A file whose `# data product:` line names another product is never overwritten: the run, and `--check`, stop with `generate_pyspark_schema_other_product` and write nothing. Give each product its own `--out`.

## After you review a change

A contract change that adds, drops or retypes a column changes the module. Regenerate, review the diff of the module in the same pull request as the contract change, and run the job's tests against it. A change to nullability changes `nullable=False` on the field and so what `spark.createDataFrame` accepts.

## Troubleshooting

| Code | Meaning and fix |
| --- | --- |
| `ERR_GENERATE_PYSPARK_SCHEMA_FAILED` | The generation failed. The message names the cause. |
| `ERR_GENERATE_PYSPARK_SCHEMA_FOREIGN_FILE` | A file at a module's path was not written by this command (it lacks the `# Generated by` header). Nothing is written. Move or rename the file, or choose another `--out`. |
| `ERR_GENERATE_PYSPARK_SCHEMA_DRIFT` | `--check` found a module that is missing, differs or is stale. Run the command without `--check` and commit the result. |
| `ERR_UNSUPPORTED_BINDING` with kind `column-type` | A column type cannot be mapped. The message names every such column and what to declare instead. See [Types that are refused](#types-that-are-refused). |
| `ERR_UNSUPPORTED_BINDING` with kind `contract-shape` | `exposes` or `contract.schema` is not a list. |
| `generate_pyspark_schema_other_product` | The directory holds a module of another data product with the same port id. Give each product its own `--out`. |
